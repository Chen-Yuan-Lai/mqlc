# 基礎設施失敗停止 run，模型的失敗記成答錯

一次 run 中的每個失敗都歸入下列三類之一。基礎設施無法使用（LLM API 錯誤、rate 或額度限制、網路、MongoDB 連不上或認證失敗、arm 需要的 knowledge 檔不存在或無法解析，例如還沒對某個資料庫跑 `mqlc profile`）時，run 立刻停下，這題不寫紀錄，重跑時從這題接著做。模型自己產生的結果（回覆被 max_tokens 截斷、無法解析、含寫入 stage 被拒、執行錯誤）則寫成該 candidate 的錯誤，計分時算答錯，續跑時不重問。反過來分類會讓分數失真且難以察覺：把資料庫斷線記成答錯，會悄悄壓低分數，續跑時又被當成已完成而跳過；把截斷當成 API 錯誤停下，每次重跑都在同一題付錢後又停住。代價是每個新後端（例如 OpenAI 相容的後端）和每種新的失敗情況都必須明確分類。MongoDB 的錯誤依錯誤類型判斷：伺服器選擇、I/O、連線池被清空、認證、DNS 屬於基礎設施，其餘都當成查詢本身的錯誤。第三類是 context overflow：prompt 估算超過後端宣告的 context window 時不送出，紀錄為 `skipped_context_overflow`，續跑時不重問；計分時不算對也不算錯，排除在所有比例的分母之外並另外計數。它不是基礎設施失敗（重跑結果一樣），也不是模型的答案。

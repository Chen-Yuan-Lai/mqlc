# 測試只有一個主要 seam，只假造 LLM，MongoDB 用真的

所有行為（knowledge 組裝、static check、repair、value correction、context overflow）都透過 `mqlc-core` 的單題 API 測試。唯一的 test double 是腳本化的 `LlmClient`，依序回傳寫好的回覆；MongoDB 一律用 testcontainers 起真的 `mongo:8.2`，不 mock。mqlc 的價值幾乎都在「pipeline 在真的 MongoDB 上會怎樣」：假的資料庫驗證不了 `$unwind` 語意、型別比較或 Extended JSON 日期。代價是測試需要 Docker、比較慢。Python 計分端（ADR 0001）另有自己的 seam：`score.score_run`，對 testcontainers 上的小型資料庫與官方 `eval_script.py` 計分，檢查 `scores.jsonl` 與 `summary.json`（整體、依 split、依資料庫的 Soft-EX / Strict-EX / Exec-Rate）；印出的表格不測。Rust 端的例外只有七個：IR round-trip 與 IR coverage（同樣經 `ir` 模組的公開 parse/serialize 介面，用 3,186 條 gold pipeline 和幾條手寫 pipeline，不需資料庫）、gold pipeline 的 static check 誤報計數（`ir::GoldCheck::of`，#12 起：對手寫的小資料集檢查依類型、依資料庫的計數與只讀 train；static check 本身仍在單題 API 測）、`mqlc bench` 的續跑、`bench::replay`（#21 起：對 `bench::run` 以假 `LlmClient` 寫出的 run 重播，檢查回報的第一個修正或校正與分數、不寫入 run 目錄、拒絕有修正的 run；它用的 `ReplayLlm` 不是 test double，而是 `mqlc replay` 實際用的 LLM，修正一律得到空回覆，答案就停在那裡）、MCP smoke test（#15 起：以 rmcp client 透過 stdio 啟動真的 `mqlc-mcp` binary，連到 testcontainers 上手寫的小型資料庫，列出工具、各呼叫一次；`validate_pipeline` 的錯誤與 CLI static check 用的 `Schema::from_official` 對同一組欄位的結果相同，`Schema::from_mdl` 就是在這裡測的，不另開 core 測試）、Claude Code backend（#16 起，ADR 0015：`bench::run` 跑 `ClaudeCodeClient`，`claude` 換成印出寫好的 stream-json transcript 的 shell script，第二個 test double；其餘照常對真的 MongoDB）、profiler。Profiler 在 `profile::profile` 測（#8 起）：對 testcontainers 上手寫的小型資料庫 profile，直接檢查產出的 MDL（欄位路徑、型別、presence、`mqlc.*` properties），並用 WrenAI 的 MDL JSON schema 驗證 `mdl.json`；經單題 API 只能看到 render 成 prompt 的文字，看不出 properties 與 Wren 合法性。auto MDL 進 prompt 的方式與 MDL 變動時拒絕續跑，仍分別在單題 API 與 `bench::run` 測。續跑在 `mqlc-core` 的 `bench::run` 測，同樣只換掉 `LlmClient`：中斷後只補缺少的 key、截掉寫到一半的最後一行、設定不同時拒絕續跑、基礎設施失敗時停止 run。CLI 層刻意不寫自動化測試：CLI 直接建立真的後端（`AnthropicClient` 或 `OpenAiClient`），要測就得另開換掉 LLM 的入口（例如改連假的 HTTP server），等於多一個 test double。兩個後端的 HTTP 轉接層同樣沒有自動化測試，各自用真的端點跑幾題確認。CLI 只負責把旗標轉成 core 的設定（後端、arm、修正、取樣）、core 之外的旗標組合檢查、依 split、`--db` 與 `--draw` 篩選、印出 core 算好的報告、輸出進度和 exit code（答錯時 `ask` 回 1、prompt 太長未送出時回 3，`bench` 提前停止時回 2）；旗標本身以 `mqlc --help` 為準。CLI 交給 core 的部分在 core 測：各 arm 的 prompt 與人工 MDL 拒絕 dev 資料庫在單題 API，manifest 記錄的設定與知識在 `bench::run`，`profile --exclude` 的 collection 與欄位在 `profile::profile`。CLI 本身沒有自動化測試，改動時要用真的 API 跑幾題手動確認。

# 測試只有一個主要 seam，只假造 LLM，MongoDB 用真的

所有行為（knowledge 組裝、static check、repair、value correction、context overflow）都透過 `mqlc-core` 的單題 API 測試。唯一的 test double 是腳本化的 `LlmClient`，依序回傳寫好的回覆；MongoDB 一律用 testcontainers 起真的 `mongo:8.2`，不 mock。mqlc 的價值幾乎都在「pipeline 在真的 MongoDB 上會怎樣」：假的資料庫驗證不了 `$unwind` 語意、型別比較或 Extended JSON 日期。代價是測試需要 Docker、比較慢。例外只有三個：IR round-trip（不需資料庫）、`mqlc bench` 的續跑、MCP smoke test。續跑在 `mqlc-core` 的 `bench::run` 測，同樣只換掉 `LlmClient`：中斷後只補缺少的 key、截掉寫到一半的最後一行、設定不同時拒絕續跑、基礎設施失敗時停止 run。CLI 層刻意不寫自動化測試：CLI 直接建立真的後端（`AnthropicClient` 或 `OpenAiClient`），要測就得另開換掉 LLM 的入口（例如改連假的 HTTP server），等於多一個 test double。兩個後端的 HTTP 轉接層同樣沒有自動化測試，各自用真的端點跑幾題確認。CLI 只負責選後端（`--backend`、`--base-url`、`--context-window`、`--model` 的必填檢查）、依 split 與 `--db` 篩選、`--limit`、依資料庫排序、輸出進度和 exit code（答錯時 `ask` 回 1、prompt 太長未送出時回 3，`bench` 提前停止時回 2），這些沒有自動化測試，改動時要用真的 API 跑幾題手動確認。
